# Map of Chaos — Application DNA

## Identity

- **Name**: Map of Chaos (MOC)
- **Type**: Personal semantic knowledge-capture and context-mapping Progressive Web Application (PWA)
- **Primary Role**: Convert unstructured personal information into an accumulating, evidence-grounded semantic context that can be explored visually.
- **Primary User**: Single user (Yudhan).
- **Core Interaction**: Dump.
- **Primary Output**: A living semantic map of persistent entities and grounded claims/relationships.

---

## DNA in One Sentence

> "Map of Chaos is a low-friction personal context engine that turns raw dumps into persistent entities and evidence-grounded claims, then projects that context into a map."

---

## Core Problem

A person does not think in database columns, taxonomy trees, or markdown frontmatter.

Information arrives as a continuous, messy stream of fragments:
- ideas;
- projects;
- businesses;
- accounts;
- people;
- activities;
- intentions;
- quantities;
- observations;
- references;
- uncertain or conditional statements.

Most tools force the user to organize before capturing. Map of Chaos solves this by allowing capture first, then making implicit structure explicit without requiring manual categorization.

---

## Core Mental Model

Map of Chaos is not fundamentally a note database. It is a **context accumulator**.

1. **Dump is evidence**: Every piece of human text is immutable evidence of a statement made at a specific point in time.
2. **Evidence contains mentions**: Surface forms identified within evidence spans.
3. **Mentions refer to entities**: Mentions resolve to persistent semantic identities.
4. **Entities accumulate claims**: Claims attach to entities additively across multiple dumps.
5. **Claims connect entities**: Relational claims establish verified edges between entities.
6. **Context projects into views**: Accumulated context can be projected into multiple specialized interfaces.
7. **The Map is a projection**: The visual graph is one spatial projection of context, not the database of truth.

## Primary Domain Primitives

- **Dump**: Captured human expression with timestamp and provenance.
- **Evidence**: Character-exact text span (`startOffset`, `endOffset`, `textSpan`) grounding extracted elements.
- **Mention**: Surface token within an evidence span with a candidate type hint.
- **Entity**: Persistent real-world or conceptual identity (`id`, `canonicalName`, `aliases`, `associatedHandles`).
- **Entity Resolution**: Decision linking a Mention to an Entity (`matched_existing`, `new_entity`, `associated_handle`, `ambiguous`).
- **Claim**: Atomic propositional assertion (`subjectEntityId`, `predicate`, `objectValue`, `qualifiers`, `temporalScope`).
- **Projection**: Downstream view model (`ThingProjection`, `EdgeProjection`) derived from accumulated context.

---

## Epistemic DNA

Map of Chaos enforces a strict epistemic boundary between human assertion and machine synthesis:

- **Human-Stated Knowledge** (`sourceOrigin: 'human_stated'`): Explicit statements directly grounded in user dumps.
- **Machine-Inferred Knowledge** (`sourceOrigin: 'ai_inferred'`): Provisional suggestions generated by heuristics or models.
- **Review States**: Every assertion carries an epistemic lifecycle:
  - `extracted`: Extracted from human text, awaiting verification.
  - `needs_review`: Flagged as ambiguous or uncertain.
  - `human_confirmed`: Explicitly validated by the user (immutable authority).
  - `rejected`: Explicitly dismissed by the user.

---

## Identity DNA

Conservative identity is the bedrock of Map of Chaos:

1. **Exact string similarity is not sufficient proof**: Identical names may refer to entirely different concepts.
2. **Lexical similarity generates candidates, not merges**: String matching can generate candidate matches for evaluation, but can never authorize an automatic merge.
3. **Context and type compatibility matter**: A social handle (`social_handle`) and a company (`company`) sharing the name `"freshbeda"` must remain distinct entities.
4. **Ambiguity is valid**: When evidence cannot distinguish between candidates, the system marks the resolution `'ambiguous'`. It never guesses.
5. **Human decisions override machine decisions**: Human overrides permanently lock resolution targets.
6. **Disparate roles share names**: Identifiers, platforms, accounts, businesses, and projects often share names without being the same entity.

---

## Context DNA

- New evidence enriches existing context when identity is established.
- Identical incoming claims reinforce existing claims by attaching new supporting evidence without duplicate rows.
- Claims accumulate additively. History is never silently overwritten.

---

## Temporal DNA

Statements have temporal scope:
- `observationTime`: When the user stated the claim.
- `temporalScope`: The temporal reality of the assertion (`past`, `present`, `future`, `recurring`, `timeless`).
- Conflicting statements across different times are classified as `temporal_shift`, not direct contradiction.
- **The Yoghurt Rule**: A statement like *"I make yoghurt for myself and eventually I will sell it"* must produce two distinct claims:
  - `makes(yoghurt)`: Scope `present`, Purpose `for myself`.
  - `intends_to_sell(yoghurt)`: Scope `future`, Temporal modifier `eventually`.
  Failing to scope temporally would falsely conclude that the user currently runs a commercial dairy business.

---

## Semantic DNA

- **Quantity is not identity**: Quantity qualifiers (`quantity: 5`) do not manufacture individual ghost entities.
- **Activity is not object identity**: Stating recurring activities does not manufacture artificial transaction or order entities.
- **Mention is not entity**: A surface string in text is a mention; the persistent identity behind it is an entity.
- **Relationship is not similarity**: Relationships exist only when supported by explicit propositional claims.

---

## Evidence DNA

> "Why does the system believe this?"

Every entity, attribute, and edge must be traceable to the exact characters of raw human evidence that gave rise to it. Provenance is preserved forever.

---

## UI DNA

The interface remains lightweight, responsive, and focused on exploration:
- **Dump**: Frictionless persistent entry dock.
- **Map**: Living spatial canvas driven by D3 force simulation.
- **Wander**: Associative reflection space echoing memories without graph mutation.
- **Inbox**: Dedicated triage shelf for unverified or ambiguous items.
- **Erased**: Reversible soft-delete shelf.

---

## Technical DNA

The codebase is modern, lightweight, and strictly client-side:
- **Framework**: React 19 + TypeScript
- **Bundler**: Vite
- **Styling**: Tailwind CSS
- **Graph Simulation**: `d3-force`
- **Gestures & Motion**: `@use-gesture/react`, `motion`
- **Icons**: `lucide-react`
- **Storage**: Browser-native IndexedDB via custom `IStorageDriver`
- **Offline / PWA**: Service workers via `vite-plugin-pwa`

---

## Storage DNA

- **Single-User**: Private personal memory engine.
- **Local-First**: Data lives in the user's browser IndexedDB.
- **Browser-Resident**: No server-side relational database, cloud synchronization, or external accounts required.

---

## AI DNA

> "AI is an interpreter, not the source of truth."

- AI may assist in parsing, extraction, suggesting associations, and prompting reflection.
- AI never overwrites human statements or silently mutates the semantic model.
- The semantic core runs deterministically and offline without mandatory external LLM connectivity.

---

## Graph DNA

The graph is an ephemeral projection of semantic claims. It is **NOT** a free-form similarity network:

```
PROJECTION (CORRECT):
Entity A + Entity B + Verified Claim + Evidence Span
                       │
                       ▼
                 Visual Edge

NEVER (PROHIBITED):
Entity A + Entity B + Lexical Proximity / Similar Words
                       │
                       ▼
                 Visual Edge
```

## Product DNA

### Map of Chaos Optimizes For:
1. Low-friction capture.
2. Raw evidence preservation.
3. Persistent identity.
4. Additive context accumulation.
5. Conservative semantic interpretation.
6. Visible, grounded relationships.
7. Absolute human authority.
8. Useful spatial exploration.

### Map of Chaos Does NOT Optimize For:
- Maximum automation.
- Maximum graph density.
- Maximum AI complexity.
- Feature sprawl.
- Over-engineered schema taxonomies.

## Known Boundaries

Current intentional non-goals:
- Universal NLP / unconstrained text parsing.
- Autonomous real-world fact checking.
- Graph completion heuristics.
- External vector databases (Qdrant, Pinecone, Chroma, Mem0).
- Multi-user collaboration and cloud sync.
- Enterprise knowledge management features.

---

## Governing Principle

> "Take the chaos the user naturally produces, preserve it faithfully, discover enough structure to make it useful, and allow that structure to accumulate over time."

> "Map of Chaos should not attempt to become the smartest possible knowledge system. Its job is to become intelligent enough to be useful."
